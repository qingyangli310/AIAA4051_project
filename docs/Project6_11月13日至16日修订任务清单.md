# Project 6 11月13日至16日修订任务清单

## 阶段目标

在 11 月 16 日前完成可复现的数据与端到端小规模链路。环境先按 `environment_id` 划分为 Train 70%、Dev 10%、Held-out Test 20%，三者两两无交集。ID 单错误与 OOD 双错误不是两套环境划分，而是同一批 Held-out Test 基础样本上的配对条件，统一使用 `base_sample_id` 关联。

主实验先完成 6×6。7×7 或高密度 6×6 仅在核心链路验收通过且时间允许时追加；本阶段不新增 5×5 主实验。

## 11月13日

### 成员 A 数据与 Executor

- 获取官方 PPNL `single_goal` 数据，记录 URL、commit、命令、日期、文件记录数和校验值。
- 建立 loader 与统一网格结构，冻结坐标、动作和 0-based 错误步骤规则。
- 实现非法动作、越界、障碍碰撞和未到终点四类检测。
- 为 5 至 10 条样例输出完整 executor trace。

交付：数据清单、来源记录、loader、executor、第一批测试和联调样例。

### 成员 B Generation 与 Verification

- 冻结两类任务的 schema、文本模板和 parser。
- 覆盖多余空格、换行、空输出、非法步骤号、未知错误类型和解析失败。
- 取得项目负责人对普通 T5-small 与 Flan-T5 选择的书面确认。
- 固定 checkpoint revision、tokenizer、最大长度、解码配置和 seed。

交付：模型确认记录、schema、模板、parser、parser 测试和小样例。

### 成员 C Repair 与集成

- 冻结 Repair schema 和逐样本结果 schema。
- 统一 `no_feedback`、`self_feedback`、`executor_feedback` 三种条件。
- 跑通 mock Generate、Verify、Repair、Execute 流程。
- 冻结 Success、Feasibility、Optimality、Verification Macro-F1、first-error accuracy、Repair Success Rate 和 End-to-End Success Rate。

交付：Repair schema、pipeline 接口、mock 演示、指标定义和结果模板。

## 11月14日

### 成员 A 数据构造

- 仅用 `rows`、`cols` 和排序后的障碍物生成稳定 `environment_id`。
- 验证 start、goal 和路径变化不改变同一环境 ID。
- 完成 Train、Dev、Held-out Test 划分及无泄漏测试。
- 核验官方最短路径，并构造可行但非最优的有效路径。
- 生成替换、删除、插入和提前停止四类单错误。
- 保存 `source_plan_id`、corruption 类型、位置、seed 和 executor 标签。

### 成员 B 小规模训练

- 把 Train/Dev 转换为 Generation 与 Verification 数据。
- 检查输入截断和输出长度。
- 分别跑通少量训练 step、保存 checkpoint、日志和 Dev 预测。

### 成员 C Repair 数据与指标

- 构造不泄漏正确答案的 Repair 数据。
- 实现并测试全部基础指标。
- Optimality 固定为 `optimal_length / predicted_length`，只对成功路径计算。
- `goal_not_reached` 可以 feasible，但不能 successful。
- 明确空路径、解析失败和 executor 异常的计分规则。

## 11月15日

### 成员 A 配对 ID 与 OOD 条件

- 在同一批 Held-out Test 基础样本上生成 ID 单错误和 OOD 双错误版本。
- 每对样本共享 `environment_id` 和 `base_sample_id`。
- 双错误由两个独立操作产生，保存两个 corruption 的类型、位置和 seed。
- 排除错误相互抵消、第二错误完全退化等样本。
- 用 executor 重新计算实际第一次错误和原因。

### 成员 B 真实预测

- 对固定 20 至 50 条样本运行 Generation 与 Verification。
- 保存 raw output、parse status、结构化预测、checkpoint revision、配置和推理命令。
- 计算 Generation 可解析率和执行成功率，以及 Verification 的 valid/invalid Macro-F1、错误类型准确率和错误步骤准确率。

### 成员 C 批量 Smoke Test

- 接入 A 的真实 executor、环境清单和配对条件。
- 接入 B 的真实预测；未完成部分必须明确标记 mock。
- 运行三种 feedback 条件并逐样本保存完整中间结果。
- 隔离单样本解析或执行异常，确保批量任务继续。
- 汇总成功案例、失败案例和接口阻塞项。

## 11月16日

### 统一验收

- Train、Dev、Held-out Test 环境两两无交集。
- ID/OOD 使用完全相同的 Held-out Test `environment_id` 集合，并由 `base_sample_id` 配对。
- 数据同时包含最短有效路径和可行但非最优有效路径。
- 单错误和双错误可由固定 seed 重复生成，标签与 executor 一致。
- Executor、parser、指标和 pipeline 测试全部通过。
- 20 至 50 条 smoke test 可从干净环境重放。
- Mock 与真实模型结果明确区分。
- 每条结果可追溯到原始样本、corruption、模型 revision、配置和随机种子。
- 展示至少一个成功案例，以及一个失败或 Repair 引入新错误的案例。
