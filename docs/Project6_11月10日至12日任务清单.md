### 任务二：设计端到端管线

C 需要编写一个最小版本的 `pipeline.py`：

```python
def run_pipeline(grid, generator, verifier, repairer, executor):
    candidate_plan = generator.generate(grid)

    verification = verifier.verify(
        grid=grid,
        plan=candidate_plan,
    )

    if verification["valid"]:
        repaired_plan = candidate_plan
    else:
        repaired_plan = repairer.repair(
            grid=grid,
            candidate_plan=candidate_plan,
            feedback=verification,
        )

    final_result = executor.execute(
        grid=grid,
        plan=repaired_plan,
    )

    return {
        "candidate_plan": candidate_plan,
        "verification": verification,
        "repaired_plan": repaired_plan,
        "final_result": final_result,
    }
```

由于 A、B 的真实模块可能尚未完成，C 可以暂时使用 mock：

```python
class MockGenerator:
    def generate(self, grid):
        return ["right", "right", "down"]


class MockVerifier:
    def verify(self, grid, plan):
        return {
            "valid": False,
            "first_error_step": 1,
            "reason": "obstacle_collision",
        }


class MockRepairer:
    def repair(self, grid, candidate_plan, feedback):
        return ["down", "right", "down", "right"]
```

只要使用模拟组件可以跑通完整流程，就达到第一阶段目标。

### 任务三：定义评价指标

#### Success Rate

```text
成功到达终点的样本数 ÷ 全部样本数
```

#### Feasibility

建议定义为：

```text
没有越界、碰撞或非法动作的计划数 ÷ 全部计划数
```

“没有发生违规但最终没有到达终点”是否算 feasible，需要团队统一并记录在实验协议中。

#### Optimality

建议至少记录：

```text
预测路径长度
最短路径长度
预测路径长度 ÷ 最短路径长度
```

需要明确该指标是否只对成功路径计算。

#### Repair Success Rate

```text
修复后成功的原始无效计划数
÷
进入 Repair 模块的无效计划数
```

#### End-to-End Success Rate

```text
完整管线最终成功的环境数
÷
全部评价环境数
```

C 不需要马上计算正式结果，但需要把定义写入实验协议。
